# Gemini Native Review Fixes Design

Date: 2026-07-21

## Goal

Fix the reviewed Gemini native regressions without broadening the existing
response aggregation behavior:

- preserve images delivered across multiple upstream SSE chunks;
- calculate repaired Flash Image usage from every preserved output image;
- filter `/v1beta/models` against the Gemini native fallback catalog;
- keep pnpm as the frontend's only dependency lock format.

## Scope

The SSE change applies only to Gemini `inlineData` parts whose `mimeType`
starts with `image/` and whose `data` is non-empty. Existing text aggregation,
tool calls, function responses, candidate metadata, terminal usage metadata,
and streaming pass-through behavior remain unchanged.

The model-list change applies only to the custom response generated by
`GeminiV1BetaListModels`. Generic `/v1/models` behavior remains unchanged.

## SSE Image Aggregation

`collectGeminiSSE` will retain image parts observed in every parsed chunk,
grouped by candidate identity. Candidate identity uses the explicit Gemini
`index` when present and otherwise uses the candidate's array position.

For each candidate, the collector will compare the incoming image sequence
with the previous image sequence:

- if the previous sequence is a prefix of the incoming sequence, the chunk is
  cumulative and only the suffix is new;
- if the incoming sequence is a prefix of the previous sequence, the chunk is
  a duplicate or rewind and adds nothing;
- otherwise the chunk is incremental and all incoming images are new.

At completion, collected images are merged into the selected aggregate
response. Images already present in that selected response are replaced by
the collected sequence for the same candidate, while non-image parts retain
their existing order and content. Candidates observed only in earlier chunks
are added to the aggregate response. This ensures the response body and the
subsequent Flash Image token repair see the same complete image set.

## Native Model Catalog

`geminiCustomModelsListResponse` will use endpoint-specific fallback IDs:

- Gemini native platform: IDs from `gemini.DefaultModels()`;
- all other platforms: the existing `defaultModelIDsForPlatform` result.

Account-derived model mappings remain the primary filter source. The native
fallback is used only when the available model list is empty, preserving the
existing custom-list semantics while allowing native-only fallback models such
as `gemini-3.1-pro-preview-customtools`.

## Frontend Lock File

Remove the untracked `frontend/package-lock.json`. The repository continues to
use `frontend/pnpm-lock.yaml`, matching the Makefile, documentation, and CI.

## Error Handling

Malformed SSE JSON continues to be ignored by the collector as before. Image
aggregation does not modify chunks or metadata when no valid output image is
present. Usage repair retains its current fail-closed behavior for unknown
sizes, inconsistent token counts, or malformed usage metadata.

## Tests

Add regression tests that fail before the implementation:

1. An aggregated SSE response with two images in separate incremental chunks
   preserves both images and repairs IMAGE usage for both.
2. A cumulative image chunk does not duplicate an image already observed.
3. A Gemini native custom list without account mappings retains
   `gemini-3.1-pro-preview-customtools`.

Run focused tests first, then `go test ./internal/service ./internal/handler
-count=1`, `go vet ./internal/service ./internal/handler`, and `git diff
--check`.
